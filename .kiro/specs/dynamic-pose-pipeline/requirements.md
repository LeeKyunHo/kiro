# Requirements — 동적 포즈 파이프라인 (Dynamic Pose Pipeline)

## 개요

`sd_batch_generator.py`의 생성 루프를 `pose_database.json`의 실제 항목 수에 맞춰
동적으로 순회하도록 전환하고, 생성 완료 후 젠잇(Genit) 규격 마크다운 호출 태그를
항목 수만큼 자동 조립·출력한다.

## 현재 상태

> **상태: 구현 완료.** 아래 "착수 시점" 표는 이 spec을 작성한 당시의 코드 상태이며,
> 기록 목적으로 남긴다. 최종 구현 결과는 `design.md` 6장(함수 시그니처)과
> 9장(리팩터링 및 보안 강화)을 참조한다.

## 요구사항

### R1. JSON 기반 동적 코드 집합 산출

**사용자 스토리:** 운영자로서 `pose_database.json`에 항목을 추가/삭제하면
파이썬 코드를 고치지 않고도 생성 대상이 자동 반영되기를 원한다.

#### 수용 기준

1. WHEN JSON에 정의된 코드가 N개일 때 THEN 시스템은 정확히 N개의 코드를 순회해야 한다.
2. WHEN JSON 키가 문자열(`"00"`, `"7"`, `"13"`)로 혼재할 때 THEN 시스템은 정수로 변환한 뒤
   **숫자 크기 기준 오름차순**으로 정렬해야 한다 (사전순 정렬 금지).
3. WHEN 코드 번호가 연속되지 않을 때(예: `00, 01, 05, 42`) THEN 시스템은 결번을 건너뛰고
   존재하는 코드만 순회하며 에러를 발생시키지 않아야 한다.
4. WHEN 정수로 변환할 수 없는 키를 만날 때 THEN 시스템은 해당 키를 건너뛰고
   경고 메시지를 출력해야 한다 (조용한 무시 금지).
5. WHEN 서로 다른 섹션에 동일한 코드가 중복 정의될 때 THEN 시스템은 경고를 출력하고
   나중에 읽은 값을 사용해야 한다.
6. WHEN 값이 빈 문자열이거나 공백뿐일 때 THEN 시스템은 해당 코드를 생성 대상에서 제외하고
   경고를 출력해야 한다.
7. WHEN 유효한 코드가 하나도 없을 때 THEN 시스템은 명확한 에러 메시지와 함께
   비정상 종료 코드(1)를 반환해야 한다.

### R2. 섹션 기반 동적 모드 분기

**사용자 스토리:** 운영자로서 JSON에 새 섹션을 만들면 그 이름을 `--mode` 값으로
바로 쓸 수 있기를 원한다.

#### 수용 기준

1. WHEN JSON의 최상위 섹션명이 `emotions`, `poses`, `outfits` 일 때 THEN
   `--mode`는 `all`, `emotions`, `poses`, `outfits` 를 모두 허용해야 한다.
2. WHEN `--mode all` 이 지정될 때 THEN 시스템은 모든 섹션의 코드를 합집합으로 순회해야 한다.
3. WHEN `--mode`에 존재하지 않는 섹션명이 지정될 때 THEN 시스템은 사용 가능한 모드
   목록을 안내하며 종료해야 한다.
4. WHEN `--mode`가 생략될 때 THEN 기본값 `all` 이 적용되어야 한다.
5. WHEN `--codes` 옵션으로 `20-29` 또는 `0,3,7` 형태가 주어질 때 THEN 시스템은
   해당 코드만 필터링해 순회해야 하며, `--mode` 보다 우선해야 한다.
6. WHEN 섹션명이 `_` 로 시작할 때 THEN 시스템은 주석 섹션으로 간주해 모드 목록에서
   제외해야 한다.
7. WHEN `--mode` 값이 `"00,05,20"` 또는 `"20-29"`, `"0-5,10"` 처럼 숫자·콤마·
   하이픈·공백으로만 구성될 때 THEN 시스템은 이를 섹션명이 아닌 **코드 표현식**으로
   판별해 `--codes` 와 동일한 경로로 처리해야 한다.
   - 판별 규칙: 정규식 `^[\s\d,\-]+$` 에 매칭되면 코드 표현식으로 간주한다.
   - 프리셋 키워드(`all`, 섹션명)와 코드 표현식은 문자 구성으로 구분되므로
     충돌하지 않는다.
8. WHEN `--help` 가 출력될 때 THEN `--mode` 의 help 문구에 JSON에서 실제로 읽어낸
   섹션명 목록이 표시되어야 한다.
   - `argparse` 의 `choices` 는 파서 생성 시점에 확정되므로 사용하지 않고,
     JSON 로드 후 검증하는 2단계 파싱으로 처리한다.
9. WHEN `--mode` 코드 표현식과 `--codes` 가 동시에 주어질 때 THEN `--codes` 가
   우선하며 시스템은 `--mode` 값이 무시됨을 경고해야 한다.

### R3. 가변 폭 코드 포맷팅

**사용자 스토리:** 운영자로서 코드가 100번을 넘어도 파일명 정렬이 유지되기를 원한다.

#### 수용 기준

1. WHEN 최대 코드가 99 이하일 때 THEN 파일명은 2자리 제로 패딩(`mika_07.webp`)을
   사용해야 한다 (기존 파일과의 하위 호환 유지).
2. WHEN 최대 코드가 100 이상일 때 THEN 파일명은 그 자릿수에 맞춰 패딩되어야 한다
   (예: `mika_007.webp`).
3. WHEN 파일명 포맷이 결정될 때 THEN 생성 루프·스킵 판정·마크다운 출력이 모두
   **동일한 폭**을 사용해야 한다.

### R4. 젠잇 규격 마크다운 자동 조립

**사용자 스토리:** 운영자로서 생성 직후 콘솔 출력을 그대로 복사해 젠잇 컨텐츠
프롬프트에 붙여넣기를 원한다.

#### 수용 기준

1. WHEN 생성이 끝날 때 THEN 시스템은 순회한 코드 개수와 **정확히 같은 수**의
   이미지 호출 라인을 출력해야 한다.
2. WHEN 호출 라인을 출력할 때 THEN 각 라인은
   `![image]({{url}}{prefix}/{prefix}_{code}.webp)` 형식이어야 한다.
3. WHEN 마크다운을 조립할 때 THEN `{{url}}` 은 치환되지 않은 리터럴로 출력되어야 한다
   (f-string 이스케이프 처리 필요).
4. WHEN 각 호출 라인을 출력할 때 THEN 해당 코드의 프롬프트 첫 태그를 라벨 주석으로
   병기해 어떤 표정/포즈인지 식별 가능해야 한다.
5. WHEN 젠잇 상태창 템플릿을 출력할 때 THEN
   `[@id=상태창|name={prefix}|title=...|status=...|desc=...]` 형식으로 조립해야 한다.
6. WHEN 생성에 실패한 코드가 있을 때 THEN 마크다운 목록은 **실제 파일이 존재하는
   코드만** 포함해야 한다.
7. WHEN 감정 매핑 예시를 출력할 때 THEN 하드코딩된 번호가 아니라 JSON의 실제
   섹션·코드 구성을 기반으로 조립해야 한다.
8. WHEN `--dry-run` 으로 실행될 때 THEN 시스템은 R4.6의 파일 실존 필터를 **우회**하고
   시뮬레이션 대상 전체(`target_codes`)를 정상 처리 목록으로 간주해 젠잇 마크다운을
   온전히 출력해야 한다.
   - 근거: dry-run은 API를 호출하지 않으므로 `success` 집계가 항상 비어 있다.
     R4.6을 그대로 적용하면 마크다운이 0줄이 되어 검증 목적을 달성할 수 없다.
9. WHEN `--dry-run` 마크다운이 출력될 때 THEN 블록 헤더에 `[DRY-RUN]` 표식이
   포함되어 실제 생성 결과가 아님을 식별할 수 있어야 한다.

### R5. 기존 기능 보존 (회귀 방지)

**사용자 스토리:** 운영자로서 개선 후에도 기존에 검증된 동작이 그대로이기를 원한다.

#### 수용 기준

1. WHEN 리팩터링이 완료될 때 THEN `save_as_webp()` 의 Pillow 변환 로직(RGBA→RGB,
   `format="WEBP"`, `quality=90`, `method=6`)은 변경되지 않아야 한다.
2. WHEN 리팩터링이 완료될 때 THEN `resolve_sampler()` 의 후보 목록 및 폴백 순서는
   유지되어야 한다.
3. WHEN 생성이 완료될 때 THEN Windows(`os.name == "nt"`)에서 탐색기 자동 오픈이
   계속 동작해야 한다.
4. WHEN 대상 파일이 이미 존재할 때 THEN 시스템은 건너뛰고 카운터에 반영해야 한다
   (중단 후 재개 지원 유지).
5. WHEN WebUI 연결이 끊길 때 THEN 시스템은 루프를 중단하고 그 시점까지의
   성공/스킵/실패 집계를 출력해야 한다.
6. WHEN 개별 코드 생성이 실패할 때 THEN 전체 배치는 중단되지 않고 다음 코드로
   진행해야 한다.

### R6. 실행 요약 리포트

#### 수용 기준

1. WHEN 배치가 끝날 때 THEN 시스템은 성공/스킵/실패 건수를 출력해야 한다.
2. WHEN 실패한 코드가 있을 때 THEN 시스템은 실패한 코드 번호 목록을 명시해야 한다.
3. WHEN 배치가 끝날 때 THEN 저장 폴더의 절대 경로를 출력해야 한다.

### R7. 모의 생성 모드 (`--mock`)

**사용자 스토리:** 운영자로서 SD WebUI가 설치되지 않은 다른 PC에서도 폴더 생성부터
파일 저장, 탐색기 오픈, 마크다운 출력까지 전체 파이프라인이 정상 동작하는지
즉시 확인하기를 원한다.

#### 수용 기준

1. WHEN `--mock` 이 지정될 때 THEN 시스템은 `http://127.0.0.1:7860` 으로의
   **어떠한 HTTP 요청도 발생시키지 않아야** 한다.
   - `generate_image()` 호출 금지
   - `resolve_sampler()` 호출도 생략하고 고정 문자열 `"(mock)"` 을 사용
2. WHEN `--mock` 이 지정될 때 THEN 시스템은 Pillow로 더미 이미지를 즉석 생성해
   실제 WebP 파일로 저장해야 한다.
3. WHEN 더미 이미지를 생성할 때 THEN 이미지에는 최소한 `{prefix}`, 코드 번호,
   섹션명, 라벨이 식별 가능하도록 텍스트로 그려져야 한다.
   - 폰트 로딩에 실패하더라도 예외 없이 기본 폰트로 폴백해야 한다.
4. WHEN 더미 이미지를 저장할 때 THEN 실제 생성 경로와 **동일한 `save_as_webp()`**
   를 경유해야 한다.
   - 근거: 저장 경로가 갈라지면 Pillow 변환 로직 자체를 검증할 수 없다.
5. WHEN 더미 이미지 해상도가 결정될 때 THEN 실제 생성과 동일한 종횡비를 유지하되
   축소된 크기(예: 208x304, 실제의 1/4)를 사용해 1초 내 완료되어야 한다.
6. WHEN `--mock` 으로 저장된 파일이 있을 때 THEN 젠잇 마크다운은 R4.6에 따라
   해당 파일들을 정상 목록으로 포함해야 한다.
7. WHEN `--mock` 마크다운이 출력될 때 THEN 블록 헤더에 `[MOCK]` 표식이 포함되어야 한다.
8. WHEN `--mock` 과 `--dry-run` 이 동시에 지정될 때 THEN `--dry-run` 이 우선하며
   파일을 쓰지 않아야 한다 (더 안전한 쪽 우선).
9. WHEN `--mock` 실행이 끝날 때 THEN 탐색기 자동 오픈이 정상 동작해야 한다.

### R8. 자체 검증 모드 (`--test`)

**사용자 스토리:** 운영자로서 `pose_database.json` 을 편집한 뒤 실제 생성을 돌리기
전에 데이터와 로직이 건전한지 즉시 진단하기를 원한다.

#### 수용 기준

1. WHEN `--test` 가 지정될 때 THEN 시스템은 아래 항목을 검사하고 각각
   `[PASS]` / `[FAIL]` / `[WARN]` 로 결과를 출력해야 한다.

   | # | 검사 항목 |
   |---|---|
   | T1 | `pose_database.json` 존재 여부 |
   | T2 | JSON 문법 정합성 (`JSONDecodeError` 위치 포함) |
   | T3 | 최상위 구조가 섹션 딕셔너리인지 |
   | T4 | 비정수 키 존재 여부 |
   | T5 | 빈/공백 프롬프트 존재 여부 |
   | T6 | 섹션 간 중복 코드 존재 여부 |
   | T7 | 유효 엔트리 1개 이상 |
   | T8 | 정수 정렬 결과가 사전순과 다른 경우 정렬 로직 정상 동작 |
   | T9 | `code_width()` 산출값이 최대 코드 자릿수와 일치 |
   | T10 | `parse_codes_expr()` 왕복 검증 (범위·열거·혼합·역순·중복) |
   | T11 | `asset_filename()` 이 예상 파일명과 일치 |
   | T12 | 마크다운 조립 결과의 라인 수 == 대상 코드 수 |
   | T13 | 마크다운에 `{{url}}` 리터럴이 정확히 포함 |

2. WHEN 모든 검사가 통과할 때 THEN 시스템은 종료 코드 `0` 을 반환해야 한다.
3. WHEN 하나 이상의 검사가 `[FAIL]` 일 때 THEN 시스템은 실패 건수를 요약하고
   종료 코드 `1` 을 반환해야 한다.
4. WHEN `--test` 가 지정될 때 THEN `--prefix` 와 `--char_prompt` 는 필수가 아니어야 한다.
   - 근거: 데이터·로직 진단이 목적이므로 캐릭터 정보 없이 실행 가능해야 한다.
5. WHEN `--test` 가 실행될 때 THEN 파일을 쓰지 않고 탐색기도 열지 않아야 한다.
6. WHEN `--test` 가 실행될 때 THEN 네트워크 요청이 발생하지 않아야 한다.
7. WHEN T10~T13 을 검사할 때 THEN 실제 구현 함수를 직접 호출해 검증해야 한다
   (로직 복제 금지).

## 제약 조건

- **불변 유지:** Pillow 변환 로직, Sampler 자동 탐색, 탐색기 오픈 로직은 그대로 둔다.

- 기존에 생성된 `{prefix}_00.webp` ~ `{prefix}_19.webp` 파일과 파일명 호환을 유지한다.
- 단독 CLI 실행이 가능해야 한다 (Kiro 없이 동작).

## 완료 기준 (Definition of Done)

1. JSON 키가 10개인 파일과 50개인 파일 모두 에러 없이 순회한다.
2. 콘솔 마크다운 호출 태그 수 == 실제 생성/존재하는 파일 수
   (`--dry-run` 시에는 대상 코드 수).
3. 비연속·비정렬·비정수 키가 섞인 JSON에서도 정상 동작하거나 명확한 경고를 낸다.
4. 기존 기능(R5) 전부 회귀 없음.
5. `python -m py_compile` / `ast.parse` 문법 검증 통과.
6. **WebUI가 설치되지 않은 환경에서** 아래 한 줄로 전체 파이프라인이 동작한다.
   ```
   python sd_batch_generator.py --prefix test --char_prompt "none" --mock
   ```
   → 폴더 생성, 더미 WebP 파일 저장, 탐색기 오픈, 젠잇 마크다운 출력까지 완료.
7. `python sd_batch_generator.py --test` 가 전 항목 `[PASS]` 로 종료 코드 0 반환.
8. `--mode 00,05,12` 형태의 코드 리스트 직접 지정이 동작한다.
