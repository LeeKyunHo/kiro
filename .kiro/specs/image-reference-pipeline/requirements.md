# Requirements — 참조 이미지 파이프라인 (Image Reference Pipeline)

## 개요

참조 이미지를 활용해 두 가지 기능을 추가한다.

1. **`--from_image`** — 참조 이미지에서 외형 태그를 역추출해 `--char_prompt` 작성을 자동화
2. **IP-Adapter 연동** — 참조 이미지의 얼굴·의상 특징을 전체 생성에 적용해 캐릭터 일관성 확보

기존 spec(`dynamic-pose-pipeline`)의 R1~R8은 그대로 유효하며, 이 문서는 그 위에
얹는 증분 요구사항이다.

## 문제 정의

현재는 텍스트 프롬프트만으로 20~30장을 생성한다. `--char_prompt "silver hair,
blue eyes"` 를 넘기면 머리색·눈색은 일치하지만 **얼굴 생김새·의상 디테일·체형이
매 장 달라진다.** 챗봇 에셋으로 쓸 때 "같은 캐릭터로 보이지 않는" 문제가 생긴다.

부차적으로, 외형 태그를 매번 손으로 작성해야 하는 부담이 있다.

## 개발 환경 제약 (중요)

이 기능은 **두 대의 PC에 걸쳐 개발**된다.

| | 노트북 (구현) | 집 PC (검증) |
|---|---|---|
| GPU / WebUI | 없음 | 있음 |
| 가능한 작업 | 코드 작성, 순수 함수 검증, 페이로드 구조 검증, 파일 I/O 검증 | 실제 API 통신, 모델명 조회, weight 튜닝, 결과 확인 |

따라서 요구사항을 **노트북에서 검증 가능한 것(R1~R6)** 과
**집 PC에서만 검증 가능한 것(R7)** 으로 명시적으로 분리한다.

원리적으로 노트북에서 불가능한 두 가지는 설계로 우회한다.

- **ControlNet 모델명** — 설치 환경마다 해시가 달라 조회가 필수 → 자동 탐지 + 수동 override
- **IP-Adapter weight** — 결과를 봐야 조정 가능 → 기본값 + CLI 노출

## 요구사항

### R1. 참조 이미지 해석

**사용자 스토리:** 운영자로서 `references/` 에 약칭과 같은 이름으로 이미지를 두면
자동으로 발견되기를 원한다.

#### 수용 기준

1. WHEN `--ref_image` 가 지정될 때 THEN 시스템은 그 경로를 그대로 사용하고
   자동 탐색을 건너뛰어야 한다.
2. WHEN `--ref_image` 가 생략될 때 THEN 시스템은 `references/{prefix}.{ext}` 를
   `.png` → `.jpg` → `.jpeg` → `.webp` 순서로 탐색해야 한다.
3. WHEN 여러 확장자가 동시에 존재할 때 THEN 위 우선순위의 첫 번째를 쓰고
   나머지가 무시됨을 경고해야 한다.
4. WHEN 참조 이미지를 찾지 못할 때 THEN 시스템은 **경고만 출력하고 텍스트
   프롬프트만으로 정상 생성해야 한다.** (에러 아님)
   - 근거: 00번을 먼저 생성해 참조로 쓰는 워크플로우에서는 참조 부재가 정상 상태다.
5. WHEN `--ref_image` 로 명시한 경로가 존재하지 않을 때 THEN 시스템은
   `ConfigError` 로 중단해야 한다.
   - 근거: 자동 탐색 실패와 달리 명시적 지정 실패는 사용자 실수다.
6. WHEN 참조 이미지 경로가 디렉터리이거나 읽을 수 없을 때 THEN 명확한
   메시지와 함께 중단해야 한다.
7. WHEN 참조 이미지 파일이 유효한 이미지가 아닐 때 THEN Pillow 로 열어
   검증하고 중단해야 한다.
8. WHEN 참조 이미지가 결정될 때 THEN base64 인코딩은 **배치당 1회만** 수행하고
   전체 루프에서 재사용해야 한다.
   - 근거: 20~50장 생성 시 매번 재인코딩하면 낭비다.

### R2. IP-Adapter 페이로드 조립

**사용자 스토리:** 개발자로서 ControlNet 페이로드 조립 로직을 WebUI 없이
검증하기를 원한다.

#### 수용 기준

1. WHEN 참조 이미지가 있을 때 THEN 시스템은 `txt2img` 페이로드에
   `alwayson_scripts.controlnet.args` 를 주입해야 한다.
2. WHEN 페이로드를 조립할 때 THEN 엔드포인트는 기존 `/sdapi/v1/txt2img` 를
   그대로 사용해야 한다. (별도 ControlNet 엔드포인트를 쓰지 않음)
3. WHEN ControlNet 유닛을 조립할 때 THEN 최소한 아래 키를 포함해야 한다.

   | 키 | 값 |
   |---|---|
   | `input_image` | base64 인코딩된 참조 이미지 |
   | `module` | 전처리기 이름 (예: `ip-adapter_clip_sdxl`) |
   | `model` | ControlNet 모델명 + 해시 |
   | `weight` | 적용 강도 |
   | `enabled` | `true` |

4. WHEN 참조 이미지가 없을 때 THEN `alwayson_scripts` 키를 **아예 추가하지
   않아야** 한다. (빈 딕셔너리도 넣지 않음)
   - 근거: 빈 `alwayson_scripts` 가 WebUI 동작에 영향을 줄 수 있다.
5. WHEN 페이로드를 조립할 때 THEN 조립 로직은 **네트워크 접근이 없는 순수
   함수**로 분리되어 `--test` 에서 직접 호출 가능해야 한다.
6. WHEN `--ref_weight` 가 지정될 때 THEN 0.0 ~ 2.0 범위를 검증하고 벗어나면
   중단해야 한다.
7. WHEN `--ref_weight` 가 생략될 때 THEN 기본값 `0.7` 을 적용해야 한다.
   - 근거: 1.0 이상은 참조 이미지의 포즈까지 전이되어 JSON 포즈 지시를 무시한다.
     0.5~0.8 이 실무 범위이며 정확한 값은 R7에서 튜닝한다.
8. WHEN 참조 이미지가 적용될 때 THEN 실행 로그에 참조 파일명과 weight 가
   표시되어야 한다.

### R3. ControlNet 모델 자동 탐지

**사용자 스토리:** 운영자로서 PC마다 다른 모델 해시를 손으로 적지 않기를 원한다.

#### 수용 기준

1. WHEN ControlNet 모델명이 필요할 때 THEN 시스템은 `/controlnet/model_list` 를
   조회해 후보 패턴과 **부분 문자열 매칭**해야 한다.
   - 근거: 모델명이 `ip-adapter_xl [4209e9f7]` 처럼 해시를 포함하며 환경마다 다르다.
2. WHEN 전처리기(module)가 필요할 때 THEN `/controlnet/module_list` 를 조회해
   동일한 방식으로 매칭해야 한다.
3. WHEN `--cn_model` / `--cn_module` 이 명시될 때 THEN 조회를 건너뛰고 그 값을
   그대로 사용해야 한다.
   - 근거: 자동 탐지가 실패하는 환경에서의 탈출구.
4. WHEN 조회 자체가 실패할 때(ControlNet 미설치, WebUI 미실행) THEN 시스템은
   경고 후 **참조 이미지 없이 생성을 계속해야** 한다.
5. WHEN 후보와 일치하는 모델이 없을 때 THEN 조회된 목록을 함께 출력해
   사용자가 `--cn_model` 로 지정할 수 있게 안내해야 한다.
6. WHEN 모델 목록을 조회할 때 THEN 배치당 1회만 수행해야 한다.
7. WHEN `--mock` / `--dry-run` / `--test` 로 실행될 때 THEN 조회를 위한
   HTTP 요청이 발생하지 않아야 한다.

### R4. 태그 역추출 (`--from_image`)

**사용자 스토리:** 운영자로서 마음에 드는 캐릭터 이미지에서 외형 태그를
자동으로 뽑아 `--char_prompt` 에 쓰기를 원한다.

#### 수용 기준

1. WHEN `--from_image PATH` 가 지정될 때 THEN 시스템은 `/sdapi/v1/interrogate` 를
   호출해 태그를 추출하고 출력한 뒤 종료해야 한다.
2. WHEN `--from_image` 가 지정될 때 THEN `--prefix` / `--char_prompt` 는
   필수가 아니어야 한다.
   - 근거: 태그를 얻는 것이 목적이며 생성을 하지 않는다.
3. WHEN interrogate 모델을 선택할 때 THEN 기본값은 `deepdanbooru` 여야 한다.
   - 근거: 이 파이프라인은 danbooru 태그 기반이다. `clip` 은 자연어 문장을
     반환해 프롬프트로 쓰기 어렵다.
4. WHEN `--interrogator clip` 이 지정될 때 THEN CLIP 모델을 사용해야 한다.
5. WHEN 태그가 추출될 때 THEN 시스템은 아래를 함께 출력해야 한다.
   - 추출된 원본 태그 문자열
   - 그대로 붙여 쓸 수 있는 실행 명령 예시
6. WHEN 추출된 태그에 성별 태그(`1girl`, `1boy` 등)가 포함될 때 THEN 경고하고
   해당 태그를 제거한 버전도 함께 제시해야 한다.
   - 근거: 성별은 `_profiles` 축에서 결정되므로 `--char_prompt` 에 들어가면
     프로필과 충돌한다. (기존 spec R7 참조)
7. WHEN WebUI 에 연결할 수 없을 때 THEN 명확한 메시지와 함께 종료 코드 1을
   반환해야 한다.
8. WHEN `--from_image` 가 파일을 찾지 못할 때 THEN `ConfigError` 로 중단해야 한다.
9. WHEN interrogate 페이로드를 조립할 때 THEN 순수 함수로 분리되어 `--test` 에서
   구조를 검증할 수 있어야 한다.

### R5. 검증 모드 확장

**사용자 스토리:** 개발자로서 WebUI 없이 새 기능의 파일 I/O 와 페이로드 구조를
검증하기를 원한다.

#### 수용 기준

1. WHEN `--mock` 으로 실행될 때 THEN 참조 이미지 **탐색과 base64 인코딩은
   실제로 수행**해야 한다. (API 호출만 생략)
   - 근거: 파일 발견 실패나 인코딩 오류는 mock 에서 잡아야 할 결함이다.
2. WHEN `--mock` 에서 참조 이미지가 적용될 때 THEN 더미 이미지에 참조 사용
   여부를 표시해야 한다.
3. WHEN `--dry-run` 으로 실행될 때 THEN 참조 이미지 탐색 결과와 weight 를
   출력해야 하지만 base64 인코딩은 생략해도 된다.
4. WHEN `--test` 로 실행될 때 THEN 아래를 검증해야 한다.

   | ID | 검사 |
   |---|---|
   | T21 | 참조 이미지 확장자 우선순위 탐색 |
   | T22 | 참조 이미지 부재 시 `None` 반환 (예외 없음) |
   | T23 | base64 인코딩·디코딩 왕복 |
   | T24 | ControlNet 유닛 딕셔너리 구조 및 필수 키 |
   | T25 | 참조 없을 때 `alwayson_scripts` 키 미주입 |
   | T26 | 참조 있을 때 `alwayson_scripts` 키 주입 및 위치 |
   | T27 | `--ref_weight` 범위 검증 |
   | T28 | interrogate 페이로드 구조 |
   | T29 | 성별 태그 필터링 |
   | T30 | 모델명 부분 문자열 매칭 |

5. WHEN `--test` 가 실행될 때 THEN 네트워크 요청이 발생하지 않아야 한다.
6. WHEN `--test` 가 참조 이미지를 필요로 할 때 THEN Pillow 로 임시 이미지를
   생성해 사용하고 검사 후 정리해야 한다.
   - 근거: 저장소에 테스트용 바이너리를 커밋하지 않는다.

### R6. 하위 호환

#### 수용 기준

1. WHEN 참조 이미지가 없을 때 THEN 기존 명령어의 동작·출력·파일명이 완전히
   동일해야 한다.
2. WHEN 새 플래그를 모두 생략할 때 THEN 기존 `--test` 23항목이 전부 통과해야 한다.
3. WHEN `references/` 폴더 자체가 없을 때 THEN 에러 없이 동작해야 한다.
4. WHEN 리팩터링이 완료될 때 THEN `save_as_webp()` 의 변환 파라미터와
   `resolve_sampler()` 의 후보 순서는 변경되지 않아야 한다.
5. WHEN 프로필 시스템과 함께 쓸 때 THEN 참조 이미지는 프로필의
   `base_positive` / `base_negative` 에 영향을 주지 않아야 한다.
   - 근거: 두 축은 독립이다. 참조는 이미지 특징, 프로필은 태그를 담당한다.

### R7. 집 PC 검증 범위 (GPU 필요)

노트북에서 원리적으로 검증할 수 없는 항목이다. 수요일 세션의 완료 기준이 된다.

#### 수용 기준

1. WHEN 집 PC 에서 `/controlnet/model_list` 를 조회할 때 THEN IP-Adapter 모델이
   목록에 존재하고 자동 탐지가 성공해야 한다.
2. WHEN 자동 탐지가 실패할 때 THEN 출력된 목록을 보고 `--cn_model` 로 지정해
   동작해야 한다.
3. WHEN `--from_image` 를 실제 이미지로 실행할 때 THEN 사용 가능한 태그가
   추출되어야 한다.
4. WHEN weight 0.5 / 0.7 / 0.9 로 같은 코드를 생성할 때 THEN 결과를 비교해
   최적값을 확정해야 한다.
5. WHEN weight 가 과도할 때 THEN 참조 이미지의 포즈가 전이되어 JSON 포즈 지시가
   무시되는 현상을 확인하고 그 임계값을 기록해야 한다.
6. WHEN 최적 weight 가 확정될 때 THEN 기본값 상수를 그 값으로 갱신해야 한다.
7. WHEN 전체 세트를 생성할 때 THEN 캐릭터 일관성이 참조 없이 생성한 것보다
   개선되었음을 육안으로 확인해야 한다.

## 제약 조건

- 외부 의존성은 기존과 동일하게 `requests`, `Pillow` 를 넘지 않는다.
- ControlNet 확장 설치는 사용자 환경 책임이며, 미설치 시에도 스크립트는 동작한다.
- 참조 이미지는 `references/` 에 두고 **git 으로 추적**한다.
  (`generated_assets` 와 달리 재생성 불가한 원본 입력이다)
- 페이로드 조립은 순수 함수로 분리해 네트워크 없이 검증 가능해야 한다.
- 기존 4가지 실행 모드(기본/`--mock`/`--dry-run`/`--test`)의 부작용 경계를
  유지한다.

## 완료 기준

### 노트북 (오늘)

1. `--test` 전 항목 통과, 종료 코드 0. (기존 23 + 신규 10 = 33항목)
2. 참조 이미지 없는 상태에서 기존 동작 완전 동일 (회귀 없음).
3. 임시 참조 이미지를 두고 `--mock` 실행 시 탐색·인코딩·페이로드 조립이
   모두 수행됨을 확인.
4. `--dry-run` 에서 참조 파일명과 weight 가 출력됨.
5. 네트워크 요청이 필요한 경로는 전부 `--cn_model` 수동 지정으로 우회 가능.
6. 수요일 체크리스트 문서 작성 완료.

### 집 PC (수요일)

R7의 7개 항목 전부 확인.
