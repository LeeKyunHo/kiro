==============================================================================

  이 폴더를 처음 받았다면 이 문서만 따라가면 됩니다.
  0장부터 순서대로 읽으세요.

  [문서 안내]
    사용법.txt          이 문서. 사람이 읽는 설치·사용 가이드
    PROJECT_GUIDE.md    AI/개발자용 상세 기술 명세 (내부 동작, 상수, 확장 방법)


==============================================================================
  0. 이 폴더는 무엇인가
==============================================================================

  로컬에서 돌아가는 Stable Diffusion WebUI에 명령을 보내서,
  캐릭터 챗봇용 표정·포즈 이미지를 한 번에 여러 장 자동 생성하는 도구입니다.

  생성이 끝나면
    - 이미지가 generated_assets 폴더에 저장되고
    - 윈도우 탐색기가 자동으로 열리고
    - 젠잇(Genit)에 붙여넣을 마크다운 호출 코드가 출력됩니다.

  핵심: 파이썬 코드를 고칠 필요가 없습니다.
        JSON 파일에 항목을 늘리면 생성 장수가 늘어납니다.
        JSON에 30개를 적으면 30장, 50개를 적으면 50장이 나옵니다.

==============================================================================

   ├─ pose_database.json        ★ 프롬프트 데이터. 여기를 편집합니다
   ├─ 사용법.txt                 이 문서

   ├─ .gitattributes            줄바꿈 정규화 설정
   │

   │   ├─ README.md
   │   └─ {약칭}.png             예: mika.png
   │
   ├─ .kiro\                    Kiro IDE 설정 (Kiro를 안 쓰면 무시해도 됨)
   │   ├─ steering\sd_char_gen.md          자동 실행 규칙
   │   └─ specs\                            설계 문서
   │       ├─ dynamic-pose-pipeline\        동적 순회·프로필

  폴더 위치는 어디든 상관없습니다.
  스크립트가 자기 파일 위치를 기준으로 동작하므로 D드라이브에 두어도 됩니다.

  단, Kiro IDE의 자동 실행 기능을 쓰려면
  .kiro\steering\sd_char_gen.md 안에 적힌 폴더 경로를 본인 경로로 수정해야 합니다.
  (현재: C:\Users\USER\kiro)


==============================================================================
  2. 설치 (최초 1회)
==============================================================================

  2-1. 파이썬 확인

    파워셸을 열고 입력:

        python --version

    3.10 이상이면 OK (3.12에서 검증됨).
    "python을 찾을 수 없습니다"가 나오면 python.org에서 설치하고,
    설치 시 "Add Python to PATH" 체크를 반드시 켜세요.

  2-2. 필요한 패키지 설치

        pip install requests pillow

    requests = WebUI와 통신
    pillow   = 이미지를 WebP로 변환

  2-3. 설치 확인

        cd "폴더경로"
        python sd_batch_generator.py --test

    화면에 [PASS]가 45개 나오면 정상입니다.
    WebUI를 켜지 않은 상태에서도 이 검사는 동작합니다.


==============================================================================
  3. WebUI 세팅 (최초 1회)
==============================================================================

  자동화 스크립트 구동과 메모리 최적화를 위한 설정입니다.
  실행 파일 세팅과 내부 UI 세팅 두 가지로 나뉩니다.

  ------------------------------------------------------------------
  3-1. 실행 파일 세팅 (webui-user.bat 수정)
  ------------------------------------------------------------------

  WebUI 설치 폴더의 webui-user.bat 파일을 우클릭 → 편집(메모장)으로 엽니다.
  set COMMANDLINE_ARGS= 줄을 찾아 다음 옵션을 추가합니다.

    ● API 활성화 (필수)

      스크립트가 이미지를 자동 생성하려면 --api 옵션이 반드시 있어야 합니다.
      기존에 적힌 옵션이 있다면 한 칸 띄우고 붙이세요.

          set COMMANDLINE_ARGS=--api

    ● GPU 및 메모리 최적화 (선택)

      VRAM 8GB 권장 (A1111 공식 위키의 8GB Nvidia 권장 조합):

          set COMMANDLINE_ARGS=--api --medvram-sdxl --xformers

      ★ --xformers 와 --opt-sdp-attention 을 같이 쓰지 마세요.

         둘 다 어텐션 최적화라 하나만 적용됩니다. 같이 적으면 어느 쪽이
         쓰이는지 알 수 없어 성능 비교가 불가능해집니다. 하나만 고르세요.

      ★ --medvram 계열은 속도를 떨어뜨립니다.

         메모리를 쪼개서 올리므로 생성이 느려집니다. 에파는 한 번에
         20~50장을 순차 생성하니 장당 손실이 누적됩니다.
         장당 5초만 느려져도 30장이면 2분 30초 차이입니다.

         OOM(메모리 부족)이 나지 않는다면 굳이 넣지 않아도 됩니다.

      옵션 강도 (아래로 갈수록 메모리는 절약되지만 느려짐)

          (없음)             가장 빠름. 8GB + SDXL 이면 OOM 위험
          --medvram-sdxl     SDXL 일 때만 절약. 속도 손실 적음  ← 권장
          --medvram          항상 절약
          --lowvram          최후 수단. 속도에 치명적. 배치 작업엔 부적합

      6GB 이하라면 --medvram 또는 --lowvram 을 씁니다.

      ★ 어느 설정이 나은지는 직접 재봐야 합니다.

         에파는 생성이 끝나면 측정 결과를 출력합니다.

             [측정] 20장 / 총 412.3초 / 장당 평균 20.6초 (최속 19.8 ~ 최저 24.1)
             [VRAM] 피크 7.21 / 8.00 GiB (90%)

         옵션을 바꿔가며 이 숫자를 비교하면 됩니다.
         (WEDNESDAY_CHECKLIST.md 의 2A단계에 절차가 있습니다)

         COMMANDLINE_ARGS 는 실행 시점에 읽히므로, 바꾼 뒤에는 콘솔 창을
         완전히 닫고 webui-user.bat 을 다시 실행해야 적용됩니다.

    ● OOM(CUDA out of memory)이 났을 때

      에파는 이미 만든 파일을 건너뜁니다. 25장에서 멈췄어도 같은 명령을
      다시 실행하면 26장부터 이어서 생성합니다.

      설정을 완벽하게 맞추지 않아도 작업은 진행되니, 여기에 시간을 너무
      많이 쓰지 마세요.

      참조 이미지(IP-Adapter)를 쓰면 VRAM 을 추가로 씁니다. 참조 없이
      되던 설정이 참조를 켜면 OOM 이 날 수 있습니다.

  ------------------------------------------------------------------
  3-2. WebUI 내부 설정 (Settings 탭)
  ------------------------------------------------------------------

  WebUI를 실행한 뒤 상단 Settings 탭에서 조치합니다.

    ● 파일 이름 패턴 초기화 (가장 중요)

      Saving images/grids 탭 → Images filename pattern 칸을
      완전히 비워야(빈칸) 합니다.

      이 칸에 [prompt_words:1] 같은 값이 들어 있으면 콜론(:) 등의
      특수문자 때문에 [WinError 87] 에러가 발생하고
      파일이 0KB로 저장됩니다.

      변경 후 반드시 상단의 Apply settings를 눌러 저장하세요.

    ● 메모리 누수 방지

      10장 연속 생성 시 메모리에 찌꺼기가 쌓이는 것을 막으려면,
      User Interface 탭에서 '생성 완료 후 VRAM 비우기' 옵션을 켜두거나
      Actions 탭의 'Clean temp dir'을 활용하세요.

  ------------------------------------------------------------------
  3-3. Forge 버전 전용 VRAM 최적화
  ------------------------------------------------------------------

  WebUI Forge를 쓰신다면 화면 상단 설정 패널을 아래처럼 맞추는 것을
  권장합니다. (RTX 4060 Ti 8GB 기준 최적값)

      UI 필터                  xl (SDXL 모델 사용 시) 또는 all
      Diffusion with Low Bits  Auto      VRAM에 맞춰 최적 비트 자동 선택
      Swap Method              Queue     순차 전송으로 충돌 에러 방지
      Swap Location            CPU       안전한 시스템 메모리 활용
      Clip skip                2         애니/서브컬처 모델 표준값

  세팅을 마쳤다면 켜져 있던 검은 콘솔 창을 완전히 닫은 후
  webui-user.bat 파일로 다시 실행해야 설정이 적용됩니다.

  3-4. 모델(체크포인트) 선택 — 놓치기 쉬움
  ------------------------------------------------------------------

  스크립트는 모델을 지정하지 않습니다.
  WebUI 화면 좌측 상단에 현재 선택된 모델이 그대로 쓰입니다.

  실행 전에 브라우저에서 http://127.0.0.1:7860 을 열고
  Stable Diffusion checkpoint 에서 쓸 모델을 골라두세요.

  ★ 해상도 주의
    스크립트는 832 x 1216 고정입니다. SDXL / Illustrious / Pony 계열
    세로 초상화 규격입니다.

    SD1.5 계열 모델을 쓰시면 이 해상도가 너무 커서 인물이 둘로 나오거나
    몸이 뒤틀립니다. SD1.5를 쓰실 거면 sd_batch_generator.py 에서
    아래 줄을 찾아 수정하세요.

        IMAGE_SIZE = (832, 1216)     →     IMAGE_SIZE = (512, 768)


==============================================================================
  4. JSON 파일 설정 (pose_database.json)
==============================================================================

  이 파일이 도구의 심장입니다. 여기에 적은 만큼 이미지가 나옵니다.
  메모장으로도 편집할 수 있지만, VS Code나 Kiro로 열면 문법 오류를
  바로 알려주니 편합니다.

  ------------------------------------------------------------------
  4-1. 전체 구조
  ------------------------------------------------------------------

  {
    "_schema":   { ... 메모. 실행에 영향 없음 ... },

    "_profiles": {
      "female": {
        "base_positive": "품질태그, ..., 1girl, solo",
        "base_negative": "품질네거티브, ..., 1boy, male"
      }
    },

    "emotions": {
      "00": "neutral expression, standing, front view",
      "01": "gentle smile, standing, soft eyes"
    },

    "poses": {
      "10": "waving hand, standing, friendly greeting",
      "11": "sitting on chair, legs together, hands on lap"
    }
  }

  구성 요소 3가지:

    (1) _ 로 시작하는 키   메모/설정용. 이미지 항목으로 세지 않음
    (2) _profiles          성별 등 캐릭터 축 프리셋
    (3) 그 외 최상위 키     포즈 섹션. 이름이 그대로 --mode 값이 됨

  ------------------------------------------------------------------
  4-2. 포즈 섹션 작성 규칙
  ------------------------------------------------------------------

  ● 번호(코드) 규칙

      - 반드시 따옴표로 감싼 문자열로 적습니다.   "00"  "7"  "105"
      - 내부적으로 숫자로 읽어서 크기순으로 정렬합니다.
      - 0 ~ 9999 범위.
      - 번호가 이어지지 않아도 됩니다.
        0, 1, 5, 42 만 있으면 그 4개만 생성합니다.
      - 섹션이 달라도 번호가 겹치면 나중에 적은 것이 이깁니다.
        섹션별로 번호대를 나누세요.

        권장 번호대 예시
            00 ~ 09   감정 / 표정
            10 ~ 19   포즈 / 동작
            20 ~ 29   의상
            30 ~ 39   상황 / 배경

  ● ★ 첫 태그가 이름표가 됩니다 (가장 중요)

      쉼표 앞까지의 내용이 콘솔 출력과 매핑 가이드에 표시됩니다.
      항목을 구별할 수 있는 말을 맨 앞에 두세요.

      [잘못된 예]
          "00": "standing, front view, neutral expression",
          "01": "standing, soft eyes, gentle smile",
          "02": "standing, looking away, shy blush",

          → 결과 출력이 이렇게 나옵니다
                standing  ->  mika_00.webp
                standing  ->  mika_01.webp
                standing  ->  mika_02.webp
            뭐가 뭔지 구분이 안 됩니다.

      [올바른 예]
          "00": "neutral expression, standing, front view",
          "01": "gentle smile, standing, soft eyes",
          "02": "shy blush, standing, looking away",

          → 결과 출력
                neutral expression  ->  mika_00.webp
                gentle smile        ->  mika_01.webp
                shy blush           ->  mika_02.webp

  ● ★ 성별 태그를 넣지 마세요

      포즈에 1girl / 1boy 를 적으면 프로필과 충돌합니다.
      성별은 _profiles 에서만 다룹니다.

      [잘못된 예]  "00": "1girl, neutral expression, standing"
      [올바른 예]  "00": "neutral expression, standing, front view"

      표정과 포즈는 남녀 공통입니다. 성별을 섞으면 같은 감정을
      남녀용으로 두 번 관리해야 합니다.

  ● 섹션 이름 규칙

      영문 단어로 짓습니다.  emotions  poses  outfits  situations
      숫자만으로 짓지 마세요. ("20" 같은 이름은 번호 목록으로 오인됩니다)

  ● 캐릭터 고유 특징은 넣지 마세요

      머리색, 눈색 같은 캐릭터 외형은 JSON이 아니라
      실행할 때 --char_prompt 로 넘깁니다.
      JSON은 여러 캐릭터가 공유하는 표정·포즈만 담습니다.

  ------------------------------------------------------------------
  4-3. _profiles 작성 규칙
  ------------------------------------------------------------------

  성별처럼 캐릭터 종류에 따라 통째로 바뀌어야 하는 부분입니다.

  현재 3종이 들어 있습니다.

      female            여성 캐릭터 (기본값)
      male              남성 캐릭터
      male_otokonoko    중성적 외형의 남성 캐릭터

  ● 형식

      "프로필이름": {
        "base_positive": "필수. 포지티브 기본 태그",
        "base_negative": "선택. 네거티브 기본 태그"
      }

  ● ★ 품질 태그를 반드시 포함시켜야 합니다

      프로필 값이 스크립트 기본값을 통째로 교체합니다.
      따라서 masterpiece, best quality 같은 품질 태그도
      각 프로필 안에 들어 있어야 합니다. 빼먹으면 품질 태그 없이 나옵니다.

      [잘못된 예]
          "male": { "base_positive": "1boy, solo" }
          → 품질 태그가 사라져서 결과물이 나빠집니다

      [올바른 예]
          "male": {
            "base_positive": "masterpiece, best quality, highly detailed,
                              clean background, soft lighting,
                              character portrait, 1boy, solo, masculine",
            "base_negative": "worst quality, low quality, blurry,
                              bad anatomy, bad hands, ...,
                              1girl, female, breasts, feminine"
          }
          (실제 JSON에서는 한 줄로 이어 씁니다)

  ● ★ 포지티브와 네거티브에 같은 말을 넣지 마세요

      male_otokonoko 프로필을 보면 포지티브에 feminine face 가 있는데
      네거티브에는 feminine 을 넣지 않았습니다. 일부러 그렇게 했습니다.
      양쪽에 같은 태그가 들어가면 모델이 모순된 지시를 받습니다.

      실수하면 --test 가 잡아줍니다.

          [WARN] T19 프로필 'female' 태그 충돌 - ['feminine']

  ● 새 프로필 추가 예시

      "female_muscular": {
        "base_positive": "masterpiece, best quality, highly detailed, clean background, soft lighting, character portrait, 1girl, solo, toned body, athletic build",
        "base_negative": "worst quality, low quality, blurry, bad anatomy, bad hands, extra fingers, deformed, watermark, signature, text, cropped, 1boy, male, beard"
      }

      추가하면 바로 --profile female_muscular 로 쓸 수 있습니다.
      코드는 손대지 않습니다.

    증상                          원인
    ---------------------------   --------------------------------------
    JSON 문법 오류 (line N)        마지막 항목 뒤에 쉼표를 남겼거나
                                  중간에 쉼표를 빼먹음
    항목이 무시됨                  번호에 따옴표를 안 붙였거나 숫자가 아님
    번호가 겹친다는 경고            두 섹션에 같은 번호를 씀
    이름표가 다 똑같음              첫 태그가 전부 동일 (4-2 참고)
    성별이 이상하게 나옴            포즈에 1girl/1boy 를 적음

    편집 후에는 항상 --test 를 돌리세요. 위 문제를 전부 잡아줍니다.


==============================================================================
  4A. 참조 이미지 (같은 캐릭터로 뽑기)
==============================================================================

  텍스트 프롬프트만으로 20장을 뽑으면 머리색·눈색은 맞지만 얼굴 생김새가
  매 장 조금씩 달라집니다. 참조 이미지를 주면 그 특징을 전체에 적용해
  일관성을 높일 수 있습니다. (IP-Adapter 기능)

  ------------------------------------------------------------------
  4A-1. 준비물
  ------------------------------------------------------------------

  WebUI 에 ControlNet 확장과 IP-Adapter 모델이 설치돼 있어야 합니다.
  없어도 스크립트는 정상 동작합니다. 경고만 띄우고 텍스트 프롬프트만
  사용해서 생성합니다.

  ------------------------------------------------------------------
  4A-2. 파일 두는 방법
  ------------------------------------------------------------------

  references 폴더에 약칭과 같은 이름으로 이미지를 넣습니다.

      kiro\
       └─ references\
           ├─ mika.png       →  --prefix mika 로 실행하면 자동 발견
           ├─ ryu.webp       →  --prefix ryu
           └─ sei.jpg        →  --prefix sei

  확장자는 png, jpg, jpeg, webp 순서로 찾습니다.
  같은 이름으로 여러 확장자가 있으면 png 를 쓰고 나머지는 경고와 함께 무시합니다.

  ------------------------------------------------------------------
  4A-3. 참조 이미지 만드는 방법 (권장)
  ------------------------------------------------------------------

  외부에서 그림을 구할 필요 없습니다. 00번을 먼저 뽑아서 그걸 참조로 씁니다.

    1단계  00번만 생성

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes" --mode 0

    2단계  결과 확인. 마음에 안 들면 지우고 다시 생성

      Remove-Item generated_assets\mika\mika_00.webp
      (다시 1단계 실행)

    3단계  확정된 이미지를 참조로 복사

      Copy-Item generated_assets\mika\mika_00.webp references\mika.webp

    4단계  나머지 생성 (참조가 자동 적용됨)

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes" --mode 1-19

  ------------------------------------------------------------------
  4A-4. 참조 이미지 고르는 기준
  ------------------------------------------------------------------

    인물 수      1명 단독        여러 명이면 특징이 섞입니다
    구도         정면 또는 3/4   얼굴 특징 추출에 유리합니다
    표정·포즈    중립            강한 포즈는 다른 번호에도 전이됩니다
    배경         단순            배경도 함께 참조됩니다
    해상도       512~1024        내부적으로 축소하므로 4K 는 낭비입니다
    화풍         모델과 유사     실사 참조 + 애니 모델은 충돌합니다

  00번이 "정면·중립 표정"이라 참조용으로 딱 맞습니다.

  ------------------------------------------------------------------
  4A-5. 강도 조절 (--ref_weight)
  ------------------------------------------------------------------

      0.0          참조 무시 (텍스트만)
      0.5 ~ 0.8    실무 범위 (기본값 0.7)
      1.0 이상     ★ 참조 이미지의 포즈까지 따라와서 JSON 포즈 지시를 무시함

      python sd_batch_generator.py --prefix mika --char_prompt "..." --ref_weight 0.6

  숫자를 올릴수록 참조 이미지를 강하게 따라갑니다. 너무 올리면 표정·포즈가
  전부 참조 이미지와 같아져서 세트를 만드는 의미가 없어집니다.

  ------------------------------------------------------------------
  4A-6. 참조 없이 한 번만 돌리기 (--no_ref)
  ------------------------------------------------------------------

  references 에 파일이 있는데 이번만 참조 없이 생성하고 싶을 때 씁니다.
  파일을 옮기지 않아도 됩니다. 참조 유/무를 비교할 때 유용합니다.

      python sd_batch_generator.py --prefix mika --char_prompt "..." --no_ref

  ------------------------------------------------------------------
  4A-7. 참조가 적용됐는지 확인하는 방법
  ------------------------------------------------------------------

  실행 시 화면에 나오는 두 줄을 보면 됩니다.

    ● 정상 적용

      [REF]  mika.png (768x1024) weight 0.7
      [CN]   ip-adapter_clip_sdxl / ip-adapter_xl [4209e9f7] (auto)

    ● 참조 파일 없음 (정상. 텍스트만으로 생성됨)

      [WARN] 참조 이미지 없음 (references/mika.*) - 텍스트 프롬프트만 사용

    ● ControlNet 미설치 등 (참조 파일은 있으나 적용 안 됨)

      [REF]  mika.png (768x1024) - ControlNet 미해석, 텍스트만 사용
      [WARN] ControlNet 목록 조회 실패 - 참조 이미지 없이 생성합니다

    ● 모델을 못 찾음 → 화면에 사용 가능 목록이 전부 출력됩니다

      [WARN] IP-Adapter 모듈/모델을 찾지 못했습니다.
             사용 가능 모듈 (12): [...]
             사용 가능 모델 (5): [...]
             --cn_module / --cn_model 로 직접 지정하세요.

      그 목록에서 ip-adapter 가 들어간 이름을 골라 이렇게 넣습니다.

      python sd_batch_generator.py --prefix mika --char_prompt "..." ^
        --cn_module "ip-adapter_clip_sdxl" --cn_model "ip-adapter_xl [4209e9f7]"


==============================================================================
  4B. 이미지에서 프롬프트 뽑아내기 (--from_image)
==============================================================================

  마음에 드는 캐릭터 이미지가 있으면 거기서 외형 태그를 자동으로 추출할 수
  있습니다. --char_prompt 를 손으로 적는 수고가 없어집니다.

      python sd_batch_generator.py --from_image references\mika.png

  --prefix 나 --char_prompt 는 필요 없습니다. 태그만 뽑고 종료합니다.
  WebUI 는 켜져 있어야 합니다.

  출력 예:

    ================================================================
      태그 추출 | mika.png (768x1024) | 모델: deepdanbooru
    ================================================================

    [원본] (12개 태그)
    1girl, solo, silver hair, blue eyes, school uniform, looking at viewer, ...

    [WARN] 성별·인원 태그가 감지되었습니다: ['1girl', 'solo']
           프로필(_profiles)에서 이미 다루므로 --char_prompt 에는 넣지 마세요.

    [권장] (10개 태그)
    silver hair, blue eyes, school uniform, looking at viewer, ...

    [그대로 실행하려면]
    python sd_batch_generator.py --prefix PREFIX --char_prompt "silver hair, ..."
    ================================================================

  ★ [권장] 쪽을 쓰세요.

     [원본]에는 1girl, solo 같은 성별·인원 태그가 들어 있습니다. 이건
     _profiles 에서 이미 처리하는 것이라 --char_prompt 에 또 넣으면 충돌합니다.
     [권장]은 그걸 빼놓은 버전입니다.

  맨 아래 명령에서 PREFIX 만 실제 약칭으로 바꿔 쓰면 됩니다.

  ------------------------------------------------------------------
  추출 모델 바꾸기
  ------------------------------------------------------------------

      --interrogator deepdanbooru   (기본값) 태그 형식. 이 도구에 적합
      --interrogator clip           자연어 문장 형식. 프롬프트로 쓰기 어려움

  DeepBooru 모델이 설치돼 있지 않으면 에러가 납니다. 그럴 때 clip 을 시도하세요.

  5. 실행 명령어
==============================================================================

  먼저 폴더로 이동합니다. (경로에 공백이 있으니 따옴표 필수)

      cd "C:\Users\USER\kiro"

  ------------------------------------------------------------------
  5-1. 옵션 목록
  ------------------------------------------------------------------

    --prefix         에셋 약칭. 영문/숫자/_/- 1~64자. (필수)
    --char_prompt    캐릭터 외형 태그. (필수)
    --profile        female / male / male_otokonoko  (생략 시 female)
    --custom_neg     이 캐릭터에만 추가할 네거티브
    --mode           생성 범위 (생략 시 all)
    --codes          번호 직접 지정. --mode 보다 우선
    --dry-run        실제 생성 없이 계획만 보기
    --mock           WebUI 없이 더미 이미지로 테스트
    --test           JSON·로직 검사만 하고 종료

  [참조 이미지 관련]  (자세한 내용은 4A장)

    --ref_image      참조 이미지 경로 직접 지정
    --ref_weight     적용 강도 0.0~2.0 (기본 0.7)
    --no_ref         참조 이미지 무시
    --cn_module      ControlNet 전처리기 수동 지정
    --cn_model       ControlNet 모델 수동 지정

  [태그 추출]  (자세한 내용은 4B장)

    --from_image     이미지에서 태그 추출 후 종료
    --interrogator   deepdanbooru (기본) 또는 clip

  ------------------------------------------------------------------
  5-2. --mode 에 넣을 수 있는 5가지
  ------------------------------------------------------------------

    all           전체            JSON에 있는 모든 번호
    emotions      섹션 이름        그 섹션만
    0,5,12        번호 나열        지정한 번호만
    10-14         번호 범위        10,11,12,13,14
    0-5,12        섞어 쓰기        0,1,2,3,4,5,12

  ------------------------------------------------------------------
  5-3. 약칭(--prefix) 규칙
  ------------------------------------------------------------------

    쓸 수 있음:   mika    rin_a    test-01    ryu2
    쓸 수 없음:   미카    a/b    ..    a b    (65자 이상)

    파일명과 젠잇 호출 코드에 그대로 들어가는 값이라 영문만 받습니다.
    한글을 넣으면 실행이 거부됩니다.

  7. 사용 예시

  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes, school uniform, detailed face"

      [PROFILE] 미지정 - 기본값 'female' 적용
      [작업 시작] 캐릭터: mika | 프로필: female | 모드: all (20장) | 폭: 2
      [저장] C:\...\kiro\generated_assets\mika
      [SAMPLER] 'DPM++ 2M Karras' 감지됨
        [00] 생성 중... 완료 -> mika_00.webp

      [작업 완료] 성공 20 / 건너뜀 0 / 실패 0

  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix ryu --char_prompt "short black hair, sharp eyes, black suit" --profile male

  ★ --profile male 을 빼먹으면 여성으로 나옵니다.
     화면에 찍히는 [PROFILE] 줄을 꼭 확인하세요.

  ------------------------------------------------------------------
  예시 3. 중성적 외형 남성 캐릭터
  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix sei --char_prompt "silver bob cut, violet eyes, oversized shirt" --profile male_otokonoko

  ------------------------------------------------------------------
  예시 4. 표정만 먼저 뽑아보기
  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes" --mode emotions

  10장만 뽑아서 화풍을 확인한 뒤, 마음에 들면 나머지를 돌립니다.
  이어서 아래를 실행하면 이미 만든 10장은 건너뛰고 나머지만 생성합니다.

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes"

  ------------------------------------------------------------------
  예시 5. 마음에 안 드는 몇 장만 다시 뽑기

      Remove-Item generated_assets\mika\mika_03.webp

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes" --mode 3,7

  ------------------------------------------------------------------

      Remove-Item -Recurse -Force generated_assets\mika
      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes"

  ------------------------------------------------------------------
  예시 7. 이 캐릭터만 특정 요소 제외하기
  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix mika --char_prompt "silver hair, blue eyes" --custom_neg "glasses, hat, jewelry"

  --custom_neg 는 프로필 네거티브에 덧붙습니다. 대체가 아닙니다.

  ------------------------------------------------------------------
  예시 8. WebUI가 없는 컴퓨터에서 테스트
  ------------------------------------------------------------------

      python sd_batch_generator.py --prefix mocktest --char_prompt "none" --mock

      (탐색기 창이 열리는 것을 확인한 뒤, 그 창을 닫고 나서 아래를 실행)

      Remove-Item -Recurse -Force generated_assets\mocktest

  가짜 이미지를 실제로 저장해서 폴더 생성부터 탐색기 열림,
  마크다운 출력까지 전 과정을 1초 안에 확인할 수 있습니다.

  ★ 삭제는 탐색기 창이 열린 다음에 하세요.

     탐색기는 스크립트가 끝난 뒤 별도로 열립니다. 열리기 전에 폴더를 지우면
     아래 경고창이 뜹니다.

         "위치를 사용할 수 없습니다.
          ...\generated_assets\mocktest 을(를) 사용할 수 없습니다."

     지우려는 폴더를 탐색기가 열려고 했을 뿐이라 실제 문제는 아닙니다.
     확인을 눌러 닫으면 되고, 생성된 파일이나 도구에는 아무 영향이 없습니다.

  ★★ 반드시 mocktest 같은 전용 약칭을 쓰고 끝나면 지우세요.

     실제 캐릭터 약칭(mika 등)으로 --mock 을 돌리면 가짜 이미지가
     실제 폴더에 남습니다. 그 뒤에 진짜 생성을 돌리면 "이미 있으니 건너뜀"
     처리되어 최종 결과물이 전부 가짜 이미지가 됩니다.


==============================================================================
  8. 세 가지 검사 모드 차이
==============================================================================

                  WebUI   파일생성   용도
    -----------   -----   --------   ------------------------------------
    --test        불필요   안 만듦    JSON 문법·데이터·로직 검사 (45항목)
    --dry-run     불필요   안 만듦    대상 목록·파일명·마크다운 미리보기
    --mock        불필요   만듦       전 과정 종단 테스트 (가짜 이미지)

  JSON을 편집한 직후에는 --test 를 먼저 돌리는 습관을 들이세요.

  ★ --dry-run 장수는 실제 생성 장수와 다를 수 있습니다.
     dry-run은 이미 있는 파일도 대상에 포함해서 보여줍니다.
     "20장 계획"이라고 나와도 15장이 이미 있으면 실제로는 5장만 생성됩니다.
     장수 예측용이 아니라 대상 확인용입니다.


==============================================================================
  9. 결과물 사용법
==============================================================================

  저장 위치

      generated_assets\{약칭}\{약칭}_{번호}.webp
      예: generated_assets\mika\mika_00.webp

  생성이 끝나면 화면에 아래 형태의 블록이 출력됩니다.

      ### mika 이미지 호출 코드
      ![image]({{url}}mika/mika_00.webp)
      ![image]({{url}}mika/mika_01.webp)
      ...

      ### mika 상태 매핑 가이드
      [emotions]
        neutral expression   ->  mika_00.webp
        gentle smile         ->  mika_01.webp

==============================================================================
  10. 문제 해결
==============================================================================

  증상                          원인 / 해결
  ---------------------------   ----------------------------------------
  WebUI 연결 불가                webui-user.bat 에 --api 가 없음
                                또는 WebUI 검은 창을 닫았음

  파일이 0KB / WinError 87       WebUI Settings → Saving images/grids →
                                Images filename pattern 을 비우고 Apply

  python을 찾을 수 없습니다       파이썬 미설치 또는 PATH 미등록

  ModuleNotFoundError            pip install requests pillow

  prefix 관련 에러 메시지         약칭에 한글·공백·특수문자가 들어감

  "다음 인자가 필요합니다"         --prefix 또는 --char_prompt 를 빼먹음

  전부 "건너뜀"으로 끝남          이미 파일이 있음. 지우고 다시 실행

  남캐인데 여성으로 나옴          --profile male 을 안 붙임
                                화면의 [PROFILE] 줄 확인

  인물이 둘로 나옴 / 몸이 뒤틀림   SD1.5 모델에 832x1216 은 너무 큼
                                IMAGE_SIZE 를 (512, 768) 로 수정

  화풍이 예상과 다름              WebUI에 선택된 모델 확인
                                스크립트는 모델을 지정하지 않음

  이름표가 전부 같게 나옴          JSON 첫 태그가 중복. 4-2 참고

  "태그 충돌" 경고                포지티브와 네거티브에 같은 말이 있음
                                프로필 선택이 잘못됐거나 외형 태그 부적합

  10장 넘어가면 메모리 부족        --medvram (또는 --lowvram) 추가
                                VRAM 비우기 옵션 켜기

  "위치를 사용할 수 없습니다"       탐색기가 열리기 전에 그 폴더를 지웠음
  경고창이 뜸                     도구 문제가 아님. 확인 눌러 닫으면 끝
                                생성된 파일에는 영향 없음
                                폴더 삭제는 탐색기 창이 열린 뒤에 하세요

  참조 이미지가 적용되지 않음      화면의 [REF] / [CN] 줄을 확인 (4A-7 참고)
                                references\{약칭}.png 파일명이 맞는지
                                ControlNet 확장이 설치돼 있는지

  IP-Adapter 모델을 못 찾음        화면에 출력된 사용 가능 목록에서 골라
                                --cn_module / --cn_model 로 직접 지정

  표정·포즈가 전부 참조와 같음      --ref_weight 가 너무 높음. 0.6 이하로 낮추기

  --ref_image 경로 오류 exit 1     명시한 경로에 파일이 없음
                                자동 탐색을 쓰려면 --ref_image 를 생략

  "유효한 이미지 파일이 아닙니다"   참조 파일이 손상됐거나 이미지가 아님

  --from_image 에서 에러           WebUI 가 켜져 있는지 확인
                                DeepBooru 없으면 --interrogator clip 시도

  JSON 문법 오류 (line N)         해당 줄 근처 쉼표 확인
                                마지막 항목 뒤 쉼표는 넣지 않음


  종료 코드 (자동화에 쓸 때)

      0     정상
      1     설정·입력 오류 또는 WebUI 연결 끊김
      2     필수 옵션 누락
      130   Ctrl+C 로 중단

  11. 알아두면 좋은 것

  ● 생성 중에는 터미널을 닫지 마세요
